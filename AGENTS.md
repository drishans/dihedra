# AGENTS.md

Notes for coding agents (and people) working on Dihedra. The README covers what the app does and how it's laid out; this file covers the rules that aren't obvious from the code.

## What this is

An iPhone Duo app where the hinge angle sets the symmetry k of a Metal kaleidoscope and the ratio of an FM drone. A header-only C++20 core does the hinge mapping and the DSP. An Objective-C++ bridge (`App/Bridge/DHCore`) connects it to a SwiftUI app.

## Commands

```sh
make -C core test                          # core tests; any C++20 compiler, no Xcode
make -C core clean && make -C core test CXX=g++   # CI runs both gcc and clang
python3 tools/shader_preview.py out.png    # numpy render of the shader at several k (needs numpy, Pillow)
xcodegen                                   # regenerate Dihedra.xcodeproj from project.yml (macOS)
```

Without macOS you can run the core tests and the shader preview, but you can't build the app. Say so rather than claiming an app change works.

## Rules

**Audio thread.** The `AVAudioSourceNode` render block captures a raw `dihedra::Engine*` and calls only C++. Code that runs there must not allocate, lock, log, do I/O, touch ARC objects or call Swift or Objective-C. Data crosses threads only through the relaxed `std::atomic` fields in `Engine::controls()`. The core tests check that rendering never allocates. Keep that test passing and extend it to any new DSP.

**Core stays portable.** `core/` is header-only C++20 with no Apple headers. It must build warning-free under `-Wall -Wextra -Wpedantic -Werror` with both gcc and clang. Add a test to `core/tests/core_tests.cpp` for any new behavior.

**Feel lives in one place.** Detent, filter, spring and gain constants are all in `core/include/dihedra/Tuning.h`. Audio and visuals run the same springs from those constants so the picture and the sound glide together. Don't give them separate values.

**Shader uniforms.** `App/Render/DHShaderTypes.h` is shared by Swift, Objective-C and Metal. Keep it to plain `float` fields so the layout matches everywhere. If you change it, update `Shaders.metal`, `Renderer.swift` and `tools/shader_preview.py` together.

**Shader preview.** `tools/shader_preview.py` is a hand-kept numpy port of `Shaders.metal`. When you change the shader, port the change and render a preview to check it, including a non-integer k (a seam should appear at 6 o'clock).

**Swift.** Swift 6 with default MainActor isolation. Anything that runs off the main actor needs an explicit `nonisolated` and must be `Sendable`-safe.

**Generated and local files.** Don't commit `Dihedra.xcodeproj/`, `App/Info.plist` (both generated by XcodeGen) or `Config/Local.xcconfig` (holds the signing team ID). Change project settings in `project.yml`.

**New APIs.** The iPhone Duo hinge API (`onHingeChange`, `DeviceHinge`) arrived in iOS 27.1 and is newer than most models' training data. Check Apple's current documentation before using or changing it, and don't guess API names. Apple guarantees no hinge update rate, step size or precision, so raw angles always go through the One Euro filter in `HingeMapper`.

**Camera.** Choose cameras with `AVCaptureDeviceDirectionCoordinator` (iOS 27.1), never by `position`: on iPhone Duo the way a camera faces changes when the app moves between displays. Level the image in the shader with the rotation coordinator's angle, and keep the capture connection's `videoRotationAngle` at 0 so frames aren't rotated twice. Simulators have no cameras, so camera changes can only be checked on a device.

**Device-only checks.** Feel, hinge timing, posture changes and audio clicks can only be judged on an iPhone Duo (or partly in its simulator). The README's on-device checklist lists them. Don't mark those as verified from tests alone.

## Third-party code

From phase 3 the app vendors DSP from [pichenettes/eurorack](https://github.com/pichenettes/eurorack). Use only its MIT-licensed STM32 projects, never the GPL AVR ones. Keep Emilie Gillet's copyright notice and the MIT text next to the vendored code and in the app's acknowledgements. Never use the name "Mutable Instruments" or the names of its modules in the app's name, UI text or App Store metadata.

## Forking

The code is MIT licensed. The name Dihedra and the app icon are not part of the license. Before publishing a fork, change the app name, icon, `bundleIdPrefix` and `PRODUCT_BUNDLE_IDENTIFIER` in `project.yml`, and put your own team ID in `Config/Local.xcconfig` (copy it from `Local.xcconfig.example`).
